# flame-harness-design

flutter-flame-harness 파이프라인의 Phase 3. 최신 PRD와 `config.md`를 읽어
`lib/ui/design_tokens.dart` 상수 명세, 게임 비주얼·아트 컨셉, 에셋·오디오 소싱 계획
(런처 아이콘·스플래시 스크린 의도 포함)을 담은 디자인 문서를 생성한다.
파이프라인 상태를 `contract`로 전진시킨다.

모든 파일 스키마(`config.md`, `state.md`, `pipeline-log.md`)와 페이즈 전이 테이블은
`docs/harness/protocol.md`에 정의되어 있다 — 해당 문서를 단일 진실의 원천으로 참조한다
(§2: `state.md` 스키마; §7: `design → contract` 전이). 스키마를 여기서 재정의하지 않는다.

> `<project_root>`: 사용자가 지정한 프로젝트 생성 디렉토리(기본값=현재 작업 디렉토리).
> 이하 모든 경로는 이 값을 기준으로 한다.

## 입력

### 1. `docs/harness/config.md` 읽기

다음 키를 추출한다:

| 키 | 사용 목적 |
|---|---|
| `app_idea` | 비주얼 톤 결정 (액션 vs. 캐주얼 vs. 퍼즐) |
| `app_name` | 스플래시 헤딩·아이콘 배지에 사용 |
| `app_slug` | 에셋 디렉토리 명명 규칙 도출에 사용 |
| `default_language` | 사용자 대화 언어; 카피 샘플을 해당 언어로 작성 |

`config.md`가 없으면 다음 메시지와 함께 중단한다:
`flame-harness-design: docs/harness/config.md not found — 오케스트레이터를 먼저 실행해 부트스트랩하세요.`

### 2. 최신 PRD 읽기

`docs/harness/plans/*-prd.md` 패턴과 일치하는 파일 중 파일명 내림차순으로 첫 번째 파일을 찾는다.
PRD가 없으면 다음 메시지와 함께 중단한다:
`flame-harness-design: docs/harness/plans/ 에 PRD 없음 — flame-harness-plan을 먼저 실행하세요.`

PRD에서 다음을 추출한다:

- **장르 & 핵심 메카닉** — 색감 분위기(어두운 SF vs. 밝은 하이퍼캐주얼) 결정
- **타겟 연령 / 톤** — 연령 등급과 비주얼 스타일의 에너지 레벨
- **수익화 훅** — AdMob 배치 유형(하단 배너 → HUD 스페이싱에 영향)
- **승리/패배 조건** — 뚜렷한 비주얼 처리가 필요한 UI 상태

## 디자인 토큰

생성 페이즈 Claude가 `const` Dart 값으로 그대로 구현할 수 있도록
`lib/ui/design_tokens.dart` 명세를 작성한다. 아래 모든 하위 섹션을 포함해야 한다.

### 컬러 팔레트

장르와 톤에서 팔레트를 도출한다. 다음 템플릿을 사용하되 `<...>`를 실제 hex 색상과 근거로 교체한다:

```
Primary       <#RRGGBB>  — 메인 브랜드 / 콜투액션 색상
PrimaryDark   <#RRGGBB>  — 눌림 / 그림자 상태
Accent        <#RRGGBB>  — 하이라이트, 점수 텍스트, 파워업 글로우
Background    <#RRGGBB>  — 게임 캔버스 및 화면 배경
Surface       <#RRGGBB>  — 카드·다이얼로그·오버레이 배경
OnBackground  <#RRGGBB>  — 배경 위의 텍스트/아이콘 색상
OnSurface     <#RRGGBB>  — 서피스 위의 텍스트/아이콘 색상
Error         <#RRGGBB>  — 에러 상태, 체력 감소 플래시
```

규칙:
- 텍스트 색상과 배경 간 최소 명도 대비 4.5:1 이상.
- Background와 Primary는 동일한 온도감(둘 다 웜 또는 둘 다 쿨).
- Accent는 시각적 대비를 위해 Primary와 색상환 기준 60° 이상 차이.
- 어두운 테마(SF·호러)는 Background ≤ `#333333`; 밝은 하이퍼캐주얼은 Background ≥ `#E0E0E0`.

### 타이포그래피 스케일

각 역할별 폰트 패밀리·굵기·크기를 명세한다. 커스텀 폰트를 사용하면 Google Font 이름과
import 경로를 명시하고, 그렇지 않으면 기본값 `Roboto` 사용.

```
Display   family: <FontName>  weight: 900  size: 48 sp  — 메인 메뉴 게임 타이틀
Heading1  family: <FontName>  weight: 700  size: 32 sp  — 화면 헤딩
Heading2  family: <FontName>  weight: 700  size: 24 sp  — 섹션 헤딩, 점수
Body      family: <FontName>  weight: 400  size: 16 sp  — 일반 UI 텍스트
Caption   family: <FontName>  weight: 400  size: 12 sp  — 레이블, 툴팁
Button    family: <FontName>  weight: 600  size: 18 sp  — 주요 버튼
HUD       family: <FontName>  weight: 700  size: 20 sp  — 인게임 HUD 카운터
```

모든 크기에 `sp`(Flutter `TextScaler` 인식)를 사용한다. 게임 HUD 텍스트는
점수 카운터에 `fontFeatures: [FontFeature.tabularFigures()]`를 적용한다.

### 스페이싱 스케일

기본 단위를 정의하고 전체 스페이싱 스케일을 도출한다. 일반적인 기본값은 4 dp:

```
xs:   4 dp   — 타이트 패딩 (아이콘 레이블)
sm:   8 dp   — 카드 내부 패딩
md:  16 dp   — 표준 화면 마진
lg:  24 dp   — 섹션 간격
xl:  32 dp   — 화면 상하 패딩
xxl: 48 dp   — 히어로 영역 패딩
```

`design_tokens.dart`의 모든 레이아웃 상수는 이 명명 값을 사용한다 — UI 코드에 raw 숫자 없음.
스페이싱 값은 `const double` 필드로 적용한다.

### 반경 및 엘리베이션

```
radiusSm:   4 dp   — 칩, 작은 배지
radiusMd:   8 dp   — 카드, 다이얼로그
radiusLg:  16 dp   — 바텀 시트, 히어로 카드
radiusFull: 999 dp — 필 버튼

elevationSurface:  2 dp
elevationDialog:   8 dp
elevationFab:     12 dp
```

## 비주얼 컨셉

### 아트 디렉션

다음 5가지를 포함하여 전체 비주얼 스타일을 3–5문장으로 설명한다:

1. **아트 스타일** — 픽셀 아트 / 벡터 플랫 / 핸드드로운 / 3D 렌더 스프라이트
2. **컬러 무드** — 팔레트가 장르의 감성 톤을 어떻게 강화하는가
3. **월드 / 환경** — 배경 테마(도시·우주·숲·던전 등)
4. **캐릭터 / 적 디자인** — 실루엣 언어(귀엽고 둥근 vs. 각지고 위협적인)
5. **UI 크롬 스타일** — 오버레이가 HUD 패널·동화책 페이지·아케이드 베젤 등 어떻게 느껴지는가

설명은 스프라이트 아티스트(또는 AI 이미지 프롬프트)가 추가 안내 없이 스타일을 재현할 수
있을 만큼 구체적이어야 한다.

### 스프라이트 목록 (MVP)

MVP 핵심 루프에 필요한 모든 스프라이트를 나열한다. 각 스프라이트별로:

| 스프라이트 | 크기 (dp) | 프레임 수 | 소스 |
|---|---|---|---|
| 플레이어 아이들 | 64×64 | 4 | <아래 에셋 계획 참조> |
| 플레이어 달리기  | 64×64 | 8 | — |
| 적 A            | 48×48 | 4 | — |
| 배경 레이어 1   | 화면 너비 × 256 | 1 | — |
| ... | ... | ... | ... |

크기는 1× 스케일의 dp 기준; 에셋 파이프라인은 1×·2×·3× 모두 내보내야 한다.

### 오버레이 및 HUD 레이아웃

각 Flutter 오버레이의 레이아웃을 설명한다:

- **메인 메뉴** — 표시 요소와 대략적인 위치
- **인게임 HUD** — 점수·목숨/체력·일시정지 버튼 배치
- **일시정지 오버레이** — 재개·재시작·설정
- **게임 오버 화면** — 점수·최고 점수·재시작·AdMob 리워드 광고 부활 버튼
- **설정 화면** — BGM 토글·SFX 토글·언어 토글

각 설명은 `lib/screens/` 또는 `lib/ui/`의 Flutter 위젯과 직접 매핑된다.

## 에셋/오디오 계획

> **생성기가 소싱 없이 항상 충족할 수 있는 기본값:** 오디오 = **코드 합성**
> (`tool/build_audio.dart` → WAV); 비주얼 = **코드 드로잉** (팔레트 기반 `CustomPainter`/Flame 도형).
> 개념이 스프라이트 아트를 필요로 하는 경우에만 아래에 명세한다 — CC0 팩 또는 AI 선택;
> 생성기는 `tool/strip_bg.dart`로 소싱된 아트의 배경을 제거한다.
> 하네스는 소싱되지 않은 아트에 의존하지 않으므로, 게임은 코드 드로잉만으로도 출시 가능하다.

### 스프라이트 및 이미지 에셋

각 비주얼 에셋에 대해 다음 전략 중 하나를 명시한다:

| 전략 | 사용 시점 |
|---|---|
| **무료 팩** (itch.io / OpenGameArt / Kenney.nl) | 하이퍼캐주얼, 일반 도형 |
| **AI 생성** (Midjourney / DALL-E 프롬프트) | 특정 프롬프트가 있는 커스텀 스타일 |
| **직접 제작** | 브랜드 핵심 캐릭터 |

무료 팩을 명시하는 경우 팩 URL과 라이선스(CC0, CC-BY 등)를 제공한다.
AI 생성 에셋의 경우 사용할 정확한 프롬프트 템플릿을 작성한다
(위 아트 디렉션의 `<genre>`·`<style>` 대입).

에셋은 `pubspec.yaml`의 `flutter: assets:` 아래에 선언해야 한다.
개별 파일명이 아닌 디렉토리 항목으로 제공한다(예: `assets/images/`) — 스프라이트 추가 시
`pubspec.yaml` 수정이 필요 없도록.

### 오디오 에셋

| 사운드 | 타입 | 소스 | 라이선스 |
|---|---|---|---|
| 배경 음악 | 루프 (60–90초) | <무료 팩 URL 또는 AI 프롬프트> | <라이선스> |
| 점프 / 탭 SFX | 원샷 (< 1초) | — | — |
| 피격 / 데미지 SFX | 원샷 | — | — |
| 레벨 클리어 | 징글 (3–5초) | — | — |
| 게임 오버 | 스팅 (2–4초) | — | — |

권장 무료 소스: `freesound.org` (CC0 필터), `opengameart.org` 오디오 섹션,
`itch.io` 무료 오디오 팩.

오디오 파일은 `assets/audio/`에 저장한다. `pubspec.yaml`에 `assets/audio/`를
최상위 에셋 항목으로 추가한다.

패키지: `flame_audio` (`audioplayers` 래퍼). BGM은 `FlameAudio.bgm.play()` 사용;
자주 재생되는 SFX는 `AudioPool` 사용
(패턴은 `docs/harness/game-gotchas.md`의 **Audio** 섹션 참조).

오디오 계획 요구사항 (`docs/harness/game-gotchas.md` 기준):
- **iOS 포맷**: **WAV** 번들 (22 kHz 모노 16비트). iOS는 OGG를 안정적으로 재생하지 못함 —
  `ffmpeg -i in.ogg -ac 1 -ar 22050 -sample_fmt s16 out.wav`로 변환.
- **볼륨 캡**: 채널별 안전 캡(예: BGM ≤ 0.2, SFX ≤ 0.7)을 명시하여 `GameConfig` 기본값으로 삼는다;
  사용자 슬라이더는 캡의 분수값이다.

### flutter_launcher_icons

> 브랜딩 아트 소스: 기본적으로 생성기는 공유 코드 페인터
> (`tool/gen_icon.dart`, 디자인 토큰 색상)로 아이콘·스플래시를 그린다;
> 컨셉이 필요하다면 여기서 **AI 생성 아트**를 선택할 수 있다.
> 어느 쪽이든 생성기(§5c.9)는 `flutter_launcher_icons`/`flutter_native_splash`를 실행하고
> 로컬라이즈된 앱 표시 이름을 설정한다 — 디자인은 의도만 명세한다.

생성기가 `flutter_launcher_icons`를 구성할 수 있도록 아이콘 의도를 명세한다:

```yaml
# pubspec.yaml 발췌 (dev_dependencies)
flutter_launcher_icons:
  android: true
  ios: true
  image_path: "assets/icons/icon.png"          # 1024×1024 PNG, Android는 알파 없음
  adaptive_icon_background: "<hex colour>"     # Android 어댑티브 아이콘 배경색
  adaptive_icon_foreground: "assets/icons/icon-fg.png"  # 전경 레이어
  min_sdk_android: 21
  web:
    generate: false
```

아이콘 요구사항:
- 1024×1024 픽셀, PNG 포맷.
- 앱 아트 디렉션 준수 (캐릭터 초상화 또는 로고를 `Primary` 배경 위에).
- Android 어댑티브 아이콘: 전경 레이어는 캐릭터/로고; 배경은 `Primary` 색상.

### flutter_native_splash

`flutter_native_splash`용 스플래시 스크린 의도를 명세한다:

```yaml
# pubspec.yaml 발췌
flutter_native_splash:
  color: "<Background hex>"          # DesignTokens.background와 일치
  image: assets/images/splash.png    # 중앙 배치 로고/캐릭터, 288×288 px 권장
  android_12:
    color: "<Background hex>"
    image: assets/images/splash.png
    icon_background_color: "<Primary hex>"
  ios: true
  android: true
  web: false
```

스플래시 이미지 요구사항:
- 288×288 픽셀, 투명 배경 PNG.
- 투명 필드 위에 앱 로고 또는 메인 캐릭터 표시.
- 메인 메뉴의 비주얼 스타일과 일관성 유지.

문서에는 다음 섹션이 모두 포함되어야 한다 (하위 검증기가 이 헤딩을 grep으로 확인):

- `## Design tokens` — 팔레트 표, 타이포그래피 스케일, 스페이싱 스케일 포함
- `## Visual concept` — 아트 디렉션, 스프라이트 목록, 오버레이/HUD 레이아웃 포함
- `## Asset/audio plan` — 스프라이트 소싱 표, 오디오 표, `flutter_launcher_icons` 설정,
  `flutter_native_splash` 설정 포함

PRD와 `config.md`로 모든 섹션을 채운다; 플레이스홀더 텍스트를 남기지 않는다.

### 2. `state.md` 갱신

`docs/harness/protocol.md` §2 및 §7의 전이 규칙(`design` → `contract`)에 따라
`docs/harness/state.md`를 갱신한다. §7 규칙 2에 따라, 성공적으로 완료하고 파이프라인을
전진시키는 스킬은 동일한 원자적 쓰기로 `status: running`, `current_phase`, `next_role`을
함께 설정한다:

```yaml
status: running
current_phase: design
next_role: contract
updated_at: "<ISO-8601 UTC now>"
```

다른 키는 변경하지 않는다. 타겟 업데이트에는 `Edit`을 사용한다.

### 3. `pipeline-log.md`에 행 추가

`docs/harness/protocol.md` §6에 따라 `docs/harness/pipeline-log.md`에 한 행을 추가한다:

```
| <ISO-8601 UTC now> | complete | design | design_tokens spec written; next: contract |
```

## 오류 처리

- PRD가 없거나 비어 있으면 명확한 메시지와 함께 중단하고 `state.md`를
  `status: paused`, `pause_reason: manual_action`으로 설정한다.
- `config.md`를 읽을 수 없으면 즉시 중단한다 (부분 출력 작성 금지).
- PRD에서 장르나 톤을 확인할 수 없으면 중립 팔레트
  (어두운 배경 `#1A1A2E`, 밝은 액센트 `#E94560`)를 선택하고, 디자인 문서의
  `## Assumptions` 헤딩 아래에 해당 가정을 기록한다.
