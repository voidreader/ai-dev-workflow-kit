# 세로뷰 uGUI 구조 기준

한 프로젝트(PackingPuzzle)에서 UI를 런타임 생성 → 프리팹 자립 구조로 옮기며 얻은
기준이다. 규칙마다 **왜**와 **어겼을 때 나타나는 증상**을 같이 적었다. 증상을 보고
규칙을 역추적할 수 있어야 쓸모가 있다.

**적용 대상**: 세로 고정 모바일 게임, Screen Space-Overlay uGUI.
**적용 대상 아님**: 가로 게임, 월드 스페이스 UI, UI Toolkit, 캐릭터에 붙는 HPBar류.

---

## 0. 먼저 할 일 — 프로젝트 선언 블록

아래 표를 **프로젝트의 `CLAUDE.md` / `AGENTS.md`에 복사하고 빈칸을 채운다.**
채우지 않으면 이 스킬의 나머지를 적용할 수 없다. 프로젝트마다 답이 다른 항목만 모았다.

```markdown
## UI 구조 선언 (unity-ui-architecture)

| 항목 | 값 |
|---|---|
| 기준 해상도 | 1080 x 1920 |
| CanvasScaler | ScaleWithScreenSize / MatchWidthOrHeight 0.5 |
| 루트 Canvas 프리팹 | (예: Content/UI/HudRoot.prefab) |
| 태블릿 대응 | 가로 클램프 / 레터박스 / 대응 안 함 중 하나 |
| 클램프 여백에 보이는 것 | (예: 월드 스페이스 배경 / 단색) |
| 프리팹 편집 환경 씬 | (예: Scenes/UiPrefabEnvironment.unity) |
| 어드레서블 | 사용 여부 / 그룹 분할 기준 |
| 스프라이트 아틀라스 | 분할 기준 (예: 화면 단위 — IngameUI, LobbyUI) |
| 런타임 동적 처리 허용 목록 | (예: 화면 크기 반응 레이아웃, 데이터 바인딩 텍스트) |
```

마지막 줄이 가장 중요하다. **여기 적히지 않은 런타임 프리팹 조작은 결함으로 취급한다.**

## 1. 계층 — 루트 Canvas 하나, 그 아래 세 갈래

```
UiRoot                  Canvas(Screen Space-Overlay) + CanvasScaler + GraphicRaycaster
├ Frame                 ← 가로 클램프가 걸리는 유일한 지점
│  ├ Screens            배타적 주 화면 (로비, 인게임 HUD)
│  └ Popups             일시적으로 덮는 창 (설정, 결과, 확인)
└ Overlays              항상 최상단 (토스트, 입력 차단, 전체 딤)
```

**규칙**

- 패널 하나 = 프리팹 하나. 루트 프리팹은 이 컨테이너들과 패널 인스턴스만 가진다.
- 그리기 순서 = 계층 순서. `Screens` 안의 형제 index가 곧 앞뒤다. `SetAsLastSibling`을
  런타임에 호출해 순서를 바꾸지 않는다 — 프리팹을 봐서는 순서를 알 수 없게 된다.
- **`Overlays`는 `Frame`의 자식이 아니라 형제다.** `Frame`은 가로를 클램프하므로,
  그 안에 두면 전체 화면 딤이 태블릿에서 화면 폭보다 좁아지고 광고 오탭 차단 영역에
  구멍이 생긴다. 실제로 이 구조로 한 번 만들었다가 되돌렸다.
- 레이어 컨테이너 넷은 전부 **오프셋 0 전체 스트레치**다. 여기에 인셋·패딩을 넣지 않는다.
  화면 좌표를 정규화해 앵커로 쓰는 코드(런타임 배치)가 전부 어긋난다.

**증상 → 원인**

| 증상 | 원인 |
|---|---|
| 태블릿에서 딤이 화면을 다 안 덮음 | `Overlays`가 `Frame` 안에 있다 |
| 팝업이 HUD 뒤에 그려짐 | `Popups`가 아니라 `Screens`에 들어갔다 |
| 런타임 배치 오브젝트가 몇 픽셀 밀림 | 레이어 컨테이너에 인셋이 들어갔다 |

## 2. 해상도 — 1080 고정, 가로만 제한

`CanvasScaler`는 `1080 x 1920`, `MatchWidthOrHeight 0.5`.

세로가 긴 기기(9:20 등)에서는 이 설정만으로 논리 폭이 1080보다 넓어진다.
그대로 두면 UI가 기기마다 다른 배율로 보인다. 대응은 셋 중 하나를 **선언 블록에서 고른다**.

| 방식 | 하는 일 | 대가 |
|---|---|---|
| **가로 클램프** (권장) | `Frame`의 폭을 `min(부모폭, 부모높이 × 9/16)`로 제한 | 태블릿 좌우에 여백. 그 여백에 무엇을 보일지 정해야 한다 |
| 레터박스 | 화면 밖을 단색으로 덮음 | 여백이 죽은 공간이 된다 |
| 대응 안 함 | 아무것도 안 함 | 태블릿에서 UI가 가로로 늘어진다 |

**가로 클램프의 성질** — 폰(9:16~9:20)에서는 `부모높이 × 9/16`이 항상 부모 폭보다 커서
**발동하지 않는다**(`sizeDelta.x == 0`). 태블릿에서만 걸린다. 그래서 폰만 보고
"클램프가 동작 안 한다"고 판단하면 안 된다. 3:4 아이패드에서 확인한다.

계산은 `reference-code/UiFrameLayout.cs`, 적용은 `reference-code/UiFrame.cs`를 쓴다.
계산을 `UnityEngine` 비참조 어셈블리에 두면 에디터 없이 테스트할 수 있다.

## 3. SafeArea — 패널별로 붙인다

**`SafeAreaRoot`를 상위 하나로 통합하지 마라.** 패널마다 요구가 다르다.

- **적용한다** — 버튼·텍스트가 노치·홈 인디케이터에 걸리는 일반 패널.
- **적용하지 않는다** — 전체 화면 딤/암전. 노치 **뒤까지** 덮어야 자연스럽다.
- **적용하지 않는다** — 이미 safe area를 반영한 좌표를 런타임에 받는 오브젝트.
  safe area 부모 밑에 넣으면 **인셋이 두 번 먹는다.**

**에디터와 WebGL에서 인셋은 항상 0이다.** 눈으로 보려면 디버그 인셋 값을 강제하고
(`reference-code/SafeArea.cs`의 `DebugInsetPx`), **최종 확인은 노치 있는 실기**로 한다.
에디터 검증과 실기 검증은 보고할 때 구분한다.

인셋 합이 화면 높이를 잡아먹어 레이아웃이 무너지지 않도록 상한(예: 40%)을 두고
비례 축소한다. 이 계산도 엔진 비참조 코드에 둔다.

## 4. 프리팹 자립 — 런타임이 프리팹을 덮어쓰지 않는다

**판정 기준 한 줄**: 프리팹을 더블클릭해 열었을 때 보이는 화면이 플레이 화면과 같은가?

같지 않다면 그 차이를 만든 런타임 코드가 문제다. 스프라이트·색·폰트·크기를
런타임에 주입하는 코드(`SetSkin(...)` 류)는 제거하고 **프리팹에 직접 굽는다.**

**허용되는 동적 처리** — 선언 블록의 "런타임 동적 처리 허용 목록"에 적은 것만.
전형적으로 화면 크기·safe area에 반응하는 배치, 데이터 바인딩 텍스트/수치,
상태에 따른 활성/비활성이다. 이건 없앨 수 없고 없애서도 안 된다.

**왜 이게 무너지는가** — UI를 런타임 생성으로 먼저 만들고 나중에 프리팹으로 "이관"하면,
생성 코드가 남은 채 프리팹이 생긴다. 그 뒤로 덧붙는 수정은 자연스럽게 런타임 쪽에
쌓인다. 프리팹은 껍데기가 되고 아무도 그걸 편집하지 않게 된다. **이관 시점에
생성 코드를 같이 지우지 않은 것이 원인**이지, 나중에 쓴 사람의 잘못이 아니다.

**제거가 끝났는지는 테스트로 못 박는다** — 리플렉션으로 그 메서드·필드의 **부재**를
단언한다(`reference-code/UiLayerTests.cs` 참조). 주석으로 "쓰지 마세요"만 남기면
6개월 뒤에 다시 생긴다.

## 5. 편집 화면과 런타임 화면의 일치

Unity에는 프리팹 편집 시 배경으로 깔 씬을 지정하는 설정이 있다
(`ProjectSettings/EditorSettings.asset` → `m_PrefabUIEnvironment`).
환경 씬에 **루트 Canvas와 완전히 같은 값**의 Canvas를 만들고 그것을 지정한다.
자동화는 `reference-code/UiPrefabEnvironmentMenu.cs`.

**중첩 Canvas 함정** — 프리팹 모드에서 루트 UI 프리팹은 환경 씬 Canvas 밑에 들어가
`isRootCanvas == false`가 된다. 중첩 Canvas는 **자기 `CanvasScaler`를 무시하고 부모의
`scaleFactor`를 상속**한다. 그래서 환경 씬 Canvas 값이 루트와 다르면
"루트 프리팹을 열 때"와 "패널 하나를 단독으로 열 때"의 크기가 달라진다.

**루트 프리팹 RectTransform 함정** — 런타임에는 Overlay Canvas가 매 프레임 자기
RectTransform을 화면 크기로 덮어쓰므로 저장값이 무엇이든 결과가 같다. **그러나
중첩 Canvas는 RectTransform을 건드리지 않아 저장된 앵커가 그대로 쓰인다.**
기본값인 중앙 고정 100x100으로 저장돼 있으면 프리팹 모드에서 루트도 하위 패널도
전부 100x100으로 눌린다. **루트 프리팹의 앵커는 전체 스트레치(0,0-1,1 / 오프셋 0)로
저장한다.**

**편집 중에도 동작해야 하는 컴포넌트는 `[ExecuteAlways]`** — 가로 클램프가 대표적이다.
없으면 편집 화면에서만 클램프가 빠져 또 갈린다.

**게임 뷰 프리셋** — 기준 해상도 고정 프리셋(1080x1920)을 메뉴로 추가해두고 그걸로 본다.
화면비 0.5(1:2)에서만 드러나는 레이아웃 문제가 있다.

**프리팹 모드는 스크립트로 자동 캡처할 수 없다.** 시도한 모든 경로가 실패했고,
프리팹 스테이지를 열고 닫는 것만으로 어드레서블 그룹 항목이 삭제되는 부작용도 있었다.
**프리팹 모드 시각 확인은 사람이 직접 한다.** 자동화 계획에 넣지 마라.

## 6. 프리팹 + 어드레서블 + 아틀라스

- 패널 하나 = 프리팹 하나 = 어드레서블 항목 하나. 그룹은 로드 시점 단위로 나눈다
  (공통 / UI / 인게임 / 레벨).
- 원격 카탈로그가 필요 없으면 **로컬 전용으로 고정**한다. 나중에 필요해지면 그때 연다.
- 스프라이트 아틀라스는 **같이 보이는 것끼리** 묶는다. 화면 단위 분할(로비 / 인게임)이
  기본이고, 분할 기준은 선언 블록에 적는다.
- 최초 이관용 프리팹 생성 메뉴를 만들었다면 **재생성 경로는 예외를 던져 즉시 멈추게 한다.**
  "없으면 만든다"로 두면 평소엔 무해하지만, 프리팹이 사라진 날 손으로 재설계된 구조를
  옛 코드가 덮어쓴다. **프리팹이 사라지면 코드를 고치지 말고 git에서 복원한다.**

## 7. 회귀 테스트 — 글이 아니라 이게 규칙을 지킨다

`reference-code/UiLayerTests.cs`를 복사해 프로젝트 경로에 맞춘다. 에디터 테스트로
프리팹 에셋을 직접 읽으므로 플레이 모드가 필요 없다.

단언 항목:

1. 루트 자식이 `Frame`, `Overlays` 둘뿐이고 순서가 맞다
2. `Frame` 아래가 `Screens`, `Popups` 순이다
3. 각 패널이 정해진 레이어에 정해진 순서로 있다
4. 레이어 컨테이너 넷이 전부 오프셋 0 전체 스트레치다
5. 루트 프리팹 앵커가 전체 스트레치로 저장돼 있다
6. **같은 부모 안 형제들의 세로 구간이 겹치지 않는다**
7. 런타임 주입 메서드·필드가 존재하지 않는다 (리플렉션)
8. 스프라이트가 프리팹에 구워져 있다 (개수를 센다)

6번은 실제 사고에서 나왔다. 카드 안에 버튼을 추가하며 기존 제목과 같은 구간에
앵커를 잡았고, **불투명한 9-slice가 제목을 완전히 덮었다.** 컴파일도 되고 기존 테스트도
전부 통과했다. 최종 리뷰 전까지 아무도 몰랐다.

### 테스트를 믿기 전에 테스트를 검증하라

작성한 단언이 **실제로 실패할 수 있는지** 확인한다. 대상 기능을 잠깐 망가뜨리고
(가드 주석 처리, 스프라이트를 null로) 테스트가 **빨간불이 되는지** 본다.

이 프로젝트에서 처음 쓴 단언 둘이 기능을 지워도 통과했다.

- `Assert.That(x, Is.Not.SameAs(oldSprite))` — `x`가 `null`이어도 통과한다.
  → 기대 개수를 세는 단언으로 바꿨다.
- 값이 같을 때 쓰지 않는 가드를 검사하려 했는데, 대입문이 기존 값을 다시 읽는 구조라
  가드를 지워도 결과가 같았다. → 메서드가 `bool`을 반환하게 바꿔 가드를 관측 가능하게 만들었다.

**관측할 수 없는 것은 단언할 수 없다.** 필요하면 프로덕션 코드 시그니처를 바꾼다.

## 8. 검수 체크리스트

구조 작업을 끝냈다고 말하기 전에:

- [ ] 선언 블록이 프로젝트 지침 파일에 채워져 있다
- [ ] 루트 프리팹 앵커가 전체 스트레치로 저장돼 있다
- [ ] 각 패널 프리팹을 단독으로 열었을 때와 루트를 열었을 때 크기가 같다
- [ ] 프리팹 편집 화면과 플레이 화면이 같다 (사람이 직접 본다)
- [ ] 기준 해상도(1080x1920)와 긴 비율(1080x2400)에서 확인했다
- [ ] 태블릿 비율(3:4)에서 클램프가 걸리고 여백이 의도한 모습이다
- [ ] 노치 있는 **실기**에서 safe area를 확인했다 (에디터 확인과 구분해 보고)
- [ ] 계층 회귀 테스트가 있고, 망가뜨렸을 때 실패하는 것을 확인했다
- [ ] 선언 블록에 없는 런타임 프리팹 조작이 남아 있지 않다

## reference-code

그대로 쓰는 코드가 아니라 **복사해서 이름과 네임스페이스를 맞추는 출발점**이다.
네임스페이스는 전부 `Game.UI`로 두었다.

| 파일 | 역할 | 두는 곳 |
|---|---|---|
| `UiFrameLayout.cs` | 가로 클램프 계산 (순수 함수) | UnityEngine 비참조 어셈블리 |
| `SafeAreaMath.cs` | 인셋 음수 제거 + 상한 비례 축소 (순수 함수) | UnityEngine 비참조 어셈블리 |
| `UiFrame.cs` | 클램프 적용 `[ExecuteAlways]` | 프레젠테이션 |
| `SafeArea.cs` | `Screen.safeArea` 읽기 + 디버그 인셋 | 프레젠테이션 |
| `SafeAreaRoot.cs` | 패널에 붙이는 safe area 적용기 | 프레젠테이션 |
| `UiPrefabEnvironmentMenu.cs` | 편집 환경 씬 생성·지정 + 게임 뷰 프리셋 | 에디터 |
| `UiLayerTests.cs` | 계층·겹침·잔존 코드 회귀 테스트 | 에디터 테스트 |
